Four layers, one signed hop. Scroll: each layer takes the stage.

L1 · Operator

You, in a browser and a terminal.

The console is a SvelteKit app the same Worker serves at /admin; the CLI is a zero-dependency Node script. Both carry a session or a bearer token, and nothing else.

  • Passkey · TOTP · client-derived PBKDF2
  • ~/.config/dakflare, mode 0600

L2 · Cloudflare edge

One Worker, five pieces of state.

The Worker verifies every wire signature and serves the console. D1 is the record, KV caches the FCM token, the AuthGuard counts failed sign-ins across isolates, and one DeviceGateway per phone owns its command queue, its nonce table and its alarms.

  • Worker · D1 · KV · AuthGuard DO · DeviceGateway DO
  • one Durable Object per device

L3 · Handset

The radio, and the only copy of the key.

A Tauri app over a Rust core holds the default-SMS role, runs the flows with the screen off, and signs every request with a P-256 key the Keystore will not export.

  • keystore:v1:<iv>:<ciphertext>
  • content://sms · remoteMessaging foreground service

L4 · Carrier

A real SIM, a real SMSC, a real peer.

Messages leave as GSM-7 or UCS-2 on whichever carrier the SIM is on. No telecom SaaS sits in the path and no per-message markup is paid — that is the whole argument.

  • GSM-7 160/153 · UCS-2 70/67
  • no per-message fee

The only signed hop is between the edge and the handset — P-256, P1363, a 128-bit nonce and a ±300 s window. Everything above it is a session; everything below it is a carrier.

01 / What it is The shape

One handset, one account, no middleman.

DakFlare is not a telecom SaaS with a phone app bolted on. It is a dedicated Android handset, your own Cloudflare account, and a signed protocol between them. The phone holds the SIM; the Worker holds the record.

“The handset is the radio. The Worker is the coordinator. The console is where an operator watches both.” README
  1. 01

    Five states, no guessing.

    Live is an open socket. Synced is a contact within 15 minutes. Stale is within 24 hours. Offline is older than that. Unknown has never synced since pairing. The word is always there; colour is only the second cue.

    live synced stale offline unknown
    fleet
  2. 02

    The reply is written on the phone.

    Android hands SMS_RECEIVED to the receiver even when the app is closed. Kotlin calls the same Rust flow interpreter through JNI, then hands the reply to SmsManager. The webview is not in the path.

    JNI
  3. 03

    A key that cannot be copied out.

    Each device signs with a P-256 key. At rest it is keystore:v1:<iv>:<ciphertext>, wrapped by a non-exportable AndroidKeyStore AES-GCM key. A copied database is not a copied phone.

    Keystore
  4. 04

    The operator’s actions are on the record.

    Sign-ins, invites, factor changes and admin actions write an audit row with ids and statuses. Message bodies, phone numbers and tokens are never written there.

    audit_log
02 / How it works Inbound · answered · mirrored

The path of one message.

Two trust boundaries, four stops. The edge never holds the SIM, and the phone never needs the edge to answer.

  1. 01 · the radio

    SMS arrives

    The carrier hands the PDU to the handset. Multipart parts are joined before anything else sees them.

    SmsReceiver · goAsync()

  2. 02 · on the phone

    Stored, then answered

    The receiver opens the same libSQL database and runs the flow through the Rust core. The row is stored and the reply decided without waking the webview.

    NativeBridge.processIncoming

  3. 03 · out of the radio

    The reply leaves

    The same subscription slot sends it. One reply per message; alphanumeric senders and shortcodes are filtered before anything is sent.

    SmsManager · sendTextMessage

  4. 04 · at the edge

    The console mirrors it

    On the next sync the phone reports the row exactly as a flow would. The Worker verifies the signature, writes D1, and the console shows who answered.

    POST /v1/sms/incoming/batch

The edge is not in the reply path. A flow runs with the screen off and the app closed. The reply leaves the radio even if the Worker is unreachable; the phone keeps the authoritative copy.

The phone is not trusted blindly. Every batch is checked against a canonical string, a timestamp window and a replay-guard nonce before a single row is written.

03 / Security The factor ladder

Trust is a ladder, not a checkbox.

The console offers three sign-in factors, cheapest first. Device traffic uses a different scheme entirely: a signature, not a shared secret.

# Factor Cost on a Worker
  1. 1

    Passkey

    Default. WebAuthn with ES256, bound to the deployment’s rpId. A discoverable credential — no username to phish, no shared secret to leak.

    1–2 ms
  2. 2

    TOTP

    Optional second factor for every role: RFC 6238, six digits, 30-second step, one step of drift. Backup codes are shown once.

    µs
  3. 3

    Password

    Off unless you choose it. PBKDF2-SHA256, 210,000 iterations, run in the browser; HMAC-SHA256 with the deployment pepper on top.

    ~1 ms

A server-side PBKDF2 at 210,000 iterations costs 60–150 ms against the free tier’s 10 ms CPU budget, so client-derived is the free-tier mode. The pepper is applied after the KDF, so both modes store the same value and an upgrade re-hashes nobody.

Next on the wire: ML-DSA (FIPS 204) for device identity and ML-KEM (FIPS 203) in the device handshake. Both are gated on a keystore that can hold and sign with a post-quantum key and on a protocol version bump, so they ship as a versioned change rather than a claim.

What the phone actually signs
1METHOD 2PATH 3TIMESTAMP 4NONCE 5SHA256(body)

The Worker rebuilds this string and verifies the signature with the device's ES256 public key. A nonce window makes the same request useless twice.

At rest

keystore:v1:<iv>:<ciphertext>

Wrapped by a non-exportable AndroidKeyStore AES-GCM key. Copying the database does not copy the phone.

Not claimed

  • Delivery is not claimed yet. sent means the radio accepted the message, not that the other handset received it. A carrier report is not guaranteed.
  • No MMS. A push that is not SMS produces a notification that says so; it does not vanish.
  • No magic link yet. It needs a sender; until one is configured, the factor is advertised as unavailable.
  • No public sign-up. Accounts are invite-only; the first owner comes from dakflare auth bootstrap.
  • No post-quantum signature yet. Device identity is ES256 — P-256 with SHA-256 — because that is what the Android Keystore can hold and sign with today. ML-DSA (FIPS 204) is on the list, not in the build: a signature the handset cannot make is not a feature, and calling P-256 “military grade” would be a claim, not a parameter.
04 / Run it Self-hosted

Run it on your own account.

A Worker, one D1 database, one KV namespace and three secrets. npm run deploy builds the console into worker/public/admin first.

  • A Cloudflare account — the free tier is the target.
  • An Android handset that can hold the default-SMS role.
  • No domain required: workers.dev is on the Public Suffix List, so the passkey rpId works there.
The whole sequence, in one block 
# 1 · the edge
git clone https://github.com/JonyBepary/dakflare
cd dakflare/worker && npm install
cp wrangler.template.toml wrangler.toml
cp cloudflare.config.template.ts cloudflare.config.ts
npx wrangler d1 create sms_gateway
npx wrangler kv namespace create KV
npx wrangler d1 migrations apply sms_gateway --remote

# 2 · the three secrets
npx wrangler secret put ADMIN_TOKEN --name dakflare-worker
npx wrangler secret put BETTER_AUTH_SECRET --name dakflare-worker
npx wrangler secret put AUTH_PEPPER --name dakflare-worker

# 3 · deploy and point the CLI at it
npm run deploy
npm install -g .
dakflare init
dakflare doctor
