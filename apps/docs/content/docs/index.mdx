# DakFlare

**The handset is the radio. The Worker is the coordinator. The console is where an operator watches both.**

DakFlare pairs a dedicated Android handset (`dev.dakflare.simulator`, Tauri v2 + Rust core + Kotlin telephony) with your own Cloudflare account (Workers, 6 Durable Objects, D1, KV, R2, Queues, Workflows, Workers AI) to deliver a sovereign SMS gateway, a unified conversation hub for Telegram, WhatsApp Cloud, Messenger and Instagram, a deterministic Rust/Wasm flow engine, and an agent-operable MCP control plane—with zero third-party telecom SaaS and zero shared secrets between the phone and the edge.

# DakFlare — Sovereign Multi-Platform Messaging Hub & SMS Gateway

DakFlare pairs an Android handset (`dev.dakflare.simulator`) with a Cloudflare Worker (`dakflare-worker`). The handset holds the SIM, acts as the Android default SMS app (`android.app.role.SMS`), signs every HTTP/WebSocket request with a hardware-wrapped P-256 key (`keystore:v1:<iv>:<ciphertext>`), and evaluates `dakflare.flow/v2` graphs locally in Rust. The Worker verifies signatures and replay nonces, orchestrates six SQLite-backed Durable Objects (`DeviceGateway`, `ChannelConnection`, `Scheduler`, `AuthGuard`, `AuthorityGuard`, `AssistantAgent`), stores state in D1 (`sms_gateway`, 19 migrations `0001`–`0019`), dispatches webhooks via `WEBHOOK_QUEUE` and long delays via `FlowExecutionWorkflow`, serves the SvelteKit console at `/admin`, and exposes an agent control plane (`/mcp`, `/v1/agent/*`, `DakFlareApi` service binding).

## System Topology at a Glance

| Layer | Implementation | Responsibility |
| --- | --- | --- |
| **Handset Radio** | `simulator/` (Tauri v2 + Rust `core/` + Kotlin `bridge/` + Svelte 5) | Owns the SIM, holds `android.app.role.SMS`, wraps P-256 identity in Android Keystore, runs `simulator/flow` offline, syncs via WebSocket or polling |
| **Edge Coordinator** | `worker/` (`dakflare-worker`, TypeScript on Cloudflare Workers) | Verifies P-256 signatures & nonces, hosts REST API, Better Auth, channels (SMS, Telegram, WhatsApp Cloud, Messenger, Instagram), templates and paced scheduling, `flow.wasm` fallback, Clef System 1, and `/mcp` |
| **Durable Objects** | `DeviceGateway` (`DEVICE`), `ChannelConnection` (`CHANNEL_CONN`), `Scheduler` (`SCHEDULER`), `AuthGuard` (`AUTH_GUARD`), `AuthorityGuard` (`AUTHORITY_GUARD`), `AssistantAgent` (`ASSISTANT`) | Per-device command queue/replay/alarms, per-account channel dedupe/windows, the scheduled-send clock and pacing, account & IP lockout, live grant windows, and stateful streaming agent runtime |
| **Durable Storage & Async** | D1 (`DB` / `sms_gateway`), KV (`KV`), R2 (`MEDIA_BUCKET`), Queues (`WEBHOOK_QUEUE`, `INGEST_QUEUE`, `INGEST_DLQ`), Workflow (`FLOW_WORKFLOW`) | 19-migration SQLite ledger, FCM token cache, 24h agent attachments, SSRF-guarded webhook retries, >5s flow delays |
| **Operator Console** | `dashboard/` (Svelte 5 with SvelteKit `adapter-static` → `worker/public/admin`) | Served at `/admin`; fleet presence, messages, Svelte Flow editor with WebMCP, approvals/grants, a header **Ask** assistant, audit log, security |
| **Operator CLI** | `cli/` (`dakflare`, zero-dependency Node 22+) | 32 commands, `--agent` single-JSON contract, semantic exit codes (`0, 1, 2, 3, 4, 5, 6, 75`), `dakflare mcp serve` stdio bridge |
